Contributing

Small changes, real tests, honest status.

Before opening a change

  • Check the current feature status and roadmap.
  • Keep changes focused and preserve unrelated project work.
  • Use C++20, RAII, explicit errors, and the existing CMake/CTest structure.
  • Add regression tests for behavior changes and update documentation to match.
  • Do not add network services, account collection, telemetry, AI calls, or secrets.

Validate

Configure and run CTest on Windows using the build guide. The GitHub Actions workflow validates Debug and Release on Windows x64 and checks local website links. Do not describe GUI behavior as verified without actually launching it on a desktop.

Report issues

Use the repository issue tracker. Include minimal reproduction steps and sanitized logs. Never attach credentials or private assets.

Contributions should improve a working vertical slice.
